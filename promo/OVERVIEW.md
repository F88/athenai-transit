# Athenai Transit App 概要

本書は「あてのない乗換案内 (Athenai Transit)」の App (WebApp) 概要をまとめた説明資料です。
データパイプラインの処理は対象外とし、ユーザーが触れる App としての全体像を扱います。

出典: [README.md](../README.md) / [ABOUT.md](../ABOUT.md) / [PRD.md](../PRD.md)

---

## 1. これは何か

**目的地を入力しない、お散歩支援型の乗換案内 Web アプリ**です。
一般的な乗換案内が「目的地までの経路」や「時刻表」を提示するのに対し、Athenai Transit は「今、ここからどこへ行けるか」を提示します。目的地検索をあえて省くことで、偶然の発見と街歩きの楽しさを提供します。

- 完全フロントエンド完結 (API サーバーを持たない) の Web アプリ。
- データは静的な公共交通オープンデータに基づく。

## 2. コンセプトと提供価値

### コアバリュー

- **偶然の発見**: 行き先を決めないことで、見慣れた街に「知らないバス停」「未知のルート」を見つける。
- **街歩きの自由**: いつでも近くの乗り物を探せる安心感が、迷子になる余裕と気ままな散歩をもたらす。
- **どこでも使える「仮想統合発着案内」**: 空港や大規模ターミナルの発着案内ボードを、事業者の垣根を越えて仮想的に再現し、住宅街でもどこでも周辺の発着便をまとめて把握できる。

### 代表的なつかいかた

- **いつものお散歩**: いつものコースの少し先のバス停まで歩き、帰りの便がまだ動いている事実が、いつもより遠くへ連れ出す。
- **あてのない旅**: フリー乗車券を握り、乗ったことのない路線に飛び乗り、気になる景色で途中下車する。
- **ターミナル渡り鳥**: 接続性の高いターミナルをハブに、路線を次々乗り継いでバスネットワークの広がりを体感する。
- **地図を読む**: 複数の地図を切り替え、等高線や路地の形から街の地形と歴史を読み解く。

(その他のシナリオは [ABOUT.md](../ABOUT.md) を参照)

## 3. 対象ユーザーとデバイス

- **モバイルファースト**: スマートフォンのモバイルブラウザを最優先で設計。
- **PWA**: ホーム画面に追加 (インストール) するとブラウザ枠が消え、地図を広く使える。Android (Chrome) / iPhone・iPad (Safari) に対応。
- **デスクトップ**: 広い画面では MultiPane レイアウトで情報比較や複数ペイン閲覧に適した UI を提供する (レスポンシブに自動切替)。

## 4. 機能の概要

主要機能の一覧と詳細は [FEATURE_CATALOG.md](./FEATURE_CATALOG.md) を参照。要点は以下の通り。

- **地図**: 周辺の停留所/駅をピン表示。現在地追従、複数タイルソース切替、選択路線の停留所レイヤー。
- **エッジマーカー**: 画面外の停留所の方向を端に表示し、パンに連動して更新。
- **発着情報 (StopTimes)**: 周辺の発着を複数 View で表示。次発は相対時間、以降は絶対時刻。
- **総合発車案内**: 周辺ののりばを集約し、事業者横断の「仮想統合発着案内」として直近の発着便を俯瞰。
- **時刻表 / 行程**: 広い時間範囲の一覧と、便ごとの識別情報。
- **日時セレクター**: 任意の日時で過去・未来を探索。
- **路線図とハイライト**: 停留所を選択すると、関連する路線をハイライト表示する。
- **お気に入り (Portal / Anchor)**: Stop の登録とクイックアクセス。
- **情報レベル / 描画モード / 動作モード**: 情報量・描画負荷・表示範囲を調整。
- **多言語 / データソース選択 / 永続化 / キーボードショートカット / URL パラメータ制御**。

## 5. 画面・UI の構成

App の画面は、主に以下の要素で構成される。

- **MapView (地図)**: 地図そのものと、地図上に重なるコントロール群 (情報レベル切替、レイヤー/タイル切替、現在地ボタン、日時表示など)。停留所/駅ピン、路線図、エッジマーカーを描画する。「どこへ行けるか」を空間的に俯瞰する中心的な面。
- **StopBrowser (発着案内)**: 選択中の停留所/エリアの発着情報・時刻表を一覧する面。モバイルでは地図下部に引き上げ可能な BottomSheet、デスクトップでは MultiPane の 1 ペインとして表示される。
- **ダイアログ群**: 時刻表、行程、のりば検索、データソース選択などの共通機能、日時セレクター、ヘルプ (キーボードショートカット) など、必要に応じて開く補助 UI。

これらは独立した画面ではなく、選択・フィルター・日時などの状態を共有しており、片方の操作結果が他方へ即時反映される。

レイアウトは画面サイズに応じて自動で切り替わる (モバイルファースト)。

- **モバイル UI**: 地図を主表示とし、下部に StopBrowser の BottomSheet を重ねる。探索の主導権は常に地図側にある。
- **デスクトップ UI**: MapView・StopBrowser・補助パネルを横並び/分割で表示する MultiPane レイアウト。

また UI の情報量は **情報レベル (InfoLevel)** により `simple` / `normal` / `detailed` / `verbose` の 4 段階で制御する。

## 6. 対応データ・カバレッジ

- **データ種別**: 静的な公共交通オープンデータ。
- **モード**: 鉄道・地下鉄・モノレール・新交通・路面電車・バス・コミュニティバス・フェリー (水上バス) を含む。
- **エリア**: 首都圏を中心に、京都・名古屋・離島航路・地方フェリーから海外 (フライブルク/ヴェネツィア) まで多数のデータソースに対応。
- ユーザーは利用するデータソースを選択して読み込める (詳細な対応一覧は [ABOUT.md](../ABOUT.md))。

### 導出データ (Insight)

Athenai Transit のデータ面の特徴として、配信データには元データをそのまま変換したものだけでなく、**事前に算出した派生指標 (Insight)** が含まれる。

- **運行統計**: 停留所単位の便数 (運行頻度)・路線数・始発/終発時刻など (サービスグループ単位)。
- **地理指標**: 別路線の最寄り停留所までの距離 (交通空白の度合い)、徒歩で渡れる近隣の駅、近隣圏の乗り継ぎ利便性など。

これらは配信前にまとめて生成され、App は計算済みの値を読み込んで表示する。生成した Insight のうち一部のみを UI に表示しており、現時点で画面に出していない指標も含まれる。

## 7. できないこと・制約 (Non-goals)

- **経路検索なし**: 目的地を指定した探索は行わない (これは制約ではなくコンセプト)。
- **リアルタイム遅延情報なし**: 静的データのみを扱う。
- **データ有効期間**: 静的な時刻表データに基づくため、実際の運行状況と異なる場合があり、有効期間外の日時では正確な情報を表示できないことがある。

## 8. 技術スタック・アーキテクチャ概要

- **構成**: API サーバーを持たない完全フロントエンド完結。データ処理はすべてブラウザ内で行う。
- **フロントエンド**: React 19 + TypeScript + Vite。
- **スタイリング**: Tailwind CSS v4 + shadcn/ui (Radix UI)。
- **地図**: Leaflet.js + react-leaflet + 地理院地図タイル。
- **データ**: 事前生成済みの最適化 JSON を静的配信し、起動時にブラウザが読み込む (生成処理は本書の対象外)。
- **リポジトリパターン**: UI コンポーネントは Repository インターフェースにのみ依存し、データソースと疎結合を保つ。
